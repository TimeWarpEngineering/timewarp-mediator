# TimeWarp.Mediator 15.0.0-beta.11

`GeneratedRequestPatternAttribute` is now tested in the shape its first consumer uses: contracts with a nested `Response` in a referenced assembly, a derived attribute with `const string` templates in another referenced (metadata-only) assembly, and a `OneOf<{ContractType}.Response, SharedProblemDetails>` response template.

## Fixed

- A type name in a request pattern (a contract's `Response`, the request interface, or a response argument) no longer fails to resolve when another reference defines an internal type with the same full name. The resolver used `Compilation.GetTypeByMetadataName`, which returns null for any duplicate. It now falls back to the single same-named type the host assembly can access. Before this fix the pattern reported a false TWM013 ("request interface ... does not resolve to an interface") and emitted no `Send` arm.

## Documentation

The package readme and `documentation/architecture.md` state that contracts and derived attributes may live in referenced assemblies, and that a declaration must name the interface a behavior is constrained on (such as `TimeWarp.State.IAction`) for that behavior to close over the declared request.

Release after merge is `./bin/dev release` from a clean synced master.
