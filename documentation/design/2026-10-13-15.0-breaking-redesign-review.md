# TimeWarp.Mediator 15.0: deep code review and breaking redesign

**Date:** 2026-10-13
**Task:** 021
**Status:** Review. Decisions in section 7 need maintainer sign-off before child tasks start.
**Baseline reviewed:** 14.0.0 stable (`master` at 513d410), against the current masters of
TimeWarp.State (12.0.0-beta.13), TimeWarp.Architecture, and TimeWarp.Nuru (3.0.0-beta line).

Backward compatibility is explicitly **not** a goal of 15.0. Every consumer is a TimeWarp repo and
will be refactored with it. The goals are architectural purity and performance.

---

## 1. Verdict

14.0 shipped the right idea (a compile-time message graph with a generated dispatcher) inside a
MediatR-shaped shell. Roughly half of the repository exists only so that a MediatR user could
recognise it, and no TimeWarp consumer touches that half.

- **None of the three consumers references the reflection runtime package.** State, Architecture,
  and Nuru reference only Contracts, Generators, and (State, Architecture) Analyzers. That was
  already recorded in task 013-004 on 2026-10-11 and re-verified today.
- **The benchmark measures a path no consumer takes.** `TimeWarpGeneratedMonomorphicSend` calls
  the concrete `Mediator.Send(Ping)` overload. Every consumer injects `ISender`,
  `ISender<TScope>`, or `IMediator`, and the interface's generic `Send<TResponse>` is emitted as
  `SendCore` → `Send(object)` → type switch → `Box<T>` → unbox: three async state machines and a
  boxed response per call. Measured today, that path costs 64.8 ns and 240 B, against 65.2 ns and
  224 B for the reflection dispatcher: **through the interface, 14.0 is not faster than 13.x.**
  The void path through the interface allocates 96 B where the concrete overload allocates 0 B.
- **The contracts are `Task`-shaped, not `ValueTask`-shaped**, contrary to section 4 of the
  2026-06-17 spec. `IActionHandler` papers over this with a `ValueTask` method and an explicit
  `Task` shim.
- **Fifteen message and handler interfaces describe one dispatch shape**, and each consumer uses a
  disjoint subset: State uses `IAction` only, Architecture uses `IRequest<T>` only, Nuru uses
  `ICommand` / `IQuery` / `IIdempotentCommand` only.

The recommendation is to make 15.0 the "Phase D: Delete" the spec already planned, and to go one
step further: one dispatcher, `ValueTask`-native contracts, a closure-free pipeline delegate, and
two packages instead of four.

   else is MediatR residue.

## 3. Findings, ranked

Each finding has: what, evidence, cost today, and the 15.0 recommendation.

### F1. The reflection runtime package is 100 % compatibility code. Delete it.

- **Evidence.** `source/timewarp-mediator/` is 2,228 lines in 27 files. Classification from today's
  inventory: ~300 lines essential dispatch, ~1,080 lines DI plumbing (`MediatorServiceConfiguration`
  448, `ServiceRegistrar` 459, extensions 125), ~560 lines MediatR-parity features (pre/post
  processors, typed exception cascade via `MethodInfo.Invoke`, `HandlersOrderer`, `ObjectDetails`
  namespace-proximity ranking), ~150 lines streams, 41 lines of type forwards for 13.x binaries.
  Of the 13 configuration knobs (`TypeEvaluator`, `MaxTypesClosing`, `RegistrationTimeout`,
  `RegisterGenericHandlers`, ...) only `RegisterServicesFromAssemblies` appears in a sample; every
  other knob exists only in tests. The runtime drags with it 6,232 lines of tests (174 facts),
  eight DI-container samples (Autofac, DryIoc, Lamar, LightInject, SimpleInjector, Stashbox,
  Windsor, ASP.NET Core legacy), the publish-strategies sample, the legacy benchmark project,
  strong-name `InternalsVisibleTo`, the "two stacks" documentation, and the 13.x migration guide.
- **Cost.** Every doc page explains two stacks. Every release packs and smoke-tests four packages.
  The trim/AOT story needs `[RequiresUnreferencedCode]` annotations and a paragraph telling people
  not to suppress IL2026. The MediatR Apache attribution surface is largest here.
- **Recommendation.** Delete the package, its tests, the container samples, the legacy benchmark,
  `type-forwardings.cs`, and the 13.x sections of `migration.md`. 15.0 has one dispatcher. Keep
  the Apache notice on the Contracts files that are still derived from MediatR (the `IRequest`,
  `INotification`, `Unit` family) per the repo licensing policy.

### F2. The `ISender` path is the slow path, and it is the only path consumers use.

- **Evidence.** `mediator-emitter.cs:228-256` emits the interface methods:

  ```csharp
  public Task<TResponse> Send<TResponse>(IRequest<TResponse> request, CancellationToken ct = default)
      => SendCore<TResponse>(request, ct);
  public Task Send<TRequest>(TRequest request, CancellationToken ct = default) where TRequest : IRequest
      => Send((object)request, ct);
  private async Task<TResponse> SendCore<TResponse>(IRequest<TResponse> request, CancellationToken ct)
  {
      object? boxed = await Send((object)request, ct).ConfigureAwait(false);
      return (TResponse)boxed!;
  }
  ```

  `Send(object)` (lines 299-340) is the type switch whose arms call `Box(Dispatch_X(...))`, and
  `Box<T>` (line 161) is a second `async` method that awaits the `ValueTask<T>` and boxes it. The
  monomorphic `Send(Ping)` overload (lines 274-293) calls `Dispatch_Ping` directly, and that is
  the overload the benchmark measures. `tests/timewarp-mediator-benchmarks-comparison/dispatch-benchmarks.cs:45-47`
  holds a `TimeWarp.Mediator.Generated.Mediator` field, not an `ISender`.
- **Measured today** (same machine and BenchmarkDotNet settings as the recorded baseline; raw
  log in the task folder, `research/interface-path-benchmark.md`; the benchmark additions are in
  `tests/timewarp-mediator-benchmarks-comparison`):

  | Method | Mean | Allocated |
  |---|---|---|
  | TimeWarpLegacyMakeGenericType (reflection, `IMediator`) | 65.2 ns | 224 B |
  | TimeWarpGeneratedMonomorphicSend (concrete `Mediator.Send(Ping)`, the recorded baseline) | 29.9 ns | 96 B |
  | **TimeWarpGeneratedInterfaceSend (`ISender.Send<TResponse>(Ping)`)** | **64.8 ns** | **240 B** |
  | TimeWarpGeneratedObjectSend (`ISender.Send(object)`) | 50.5 ns | 168 B |
  | TimeWarpGeneratedMonomorphicSendUnit (concrete `Send(Nop)`, void) | 24.1 ns | 0 B |
  | **TimeWarpGeneratedInterfaceSendUnit (`ISender.Send<TRequest>(Nop)`, void)** | **43.9 ns** | **96 B** |
  | MartinothamarGenerated (`IMediator.Send`) | 8.6 ns | 24 B |

  The two 65 ns rows carry about 16-20 ns of error, so read them as "the same". The void
  monomorphic path allocates nothing; the same request through the interface allocates 96 B.

- **Cost.** Through `ISender`, the generated mediator is **no faster than the reflection
  dispatcher it replaced** (64.8 ns / 240 B against 65.2 ns / 224 B) and 7.5× slower than
  martinothamar. Every State action, every Architecture endpoint, and every Nuru handler that
  injects `ISender` pays this path. The recorded "2.3× faster than reflection" number is real
  only for code that holds the concrete generated type, which no consumer does.
- **Recommendation.** The interface methods must dispatch monomorphically. Emit the type switch
  *inside* `Send<TResponse>` and return the typed `ValueTask<TResponse>` without boxing:

  ```csharp
  public ValueTask<TResponse> Send<TResponse>(IRequest<TResponse> request, CancellationToken ct = default)
  {
      switch (request)
      {
          case Ping r:
          {
              ValueTask<Pong> vt = Dispatch_Ping(ServiceProvider, r, ct);
              return Unsafe.As<ValueTask<Pong>, ValueTask<TResponse>>(ref vt); // TResponse is Pong by construction
          }
          ...
          default: throw new NoHandlerException(request.GetType());
      }
  }
  ```

  The reinterpretation is sound because `IRequest<TResponse>` is the only way to reach the arm and
  the generator proves `TResponse == Pong` for that arm (TWM001/TWM002 guarantee one binding). The
  void overload gets the same treatment with `ValueTask`. `Send(object)` stays as the only boxing
  path and is used only by State's JSON interop. Make the interface path, not the concrete
  overload, the recorded benchmark and the merge gate (section 9).

### F3. Contracts are `Task`-shaped; the spec asked for `ValueTask`.

- **Evidence.** `IRequestHandler<TRequest,TResponse>.Handle` returns `Task<TResponse>`;
  `IRequestHandler<TRequest>.Handle` returns `Task`; `IPipelineBehavior<,>.Handle` and
  `RequestHandlerDelegate<TResponse>` return `Task<TResponse>`; `INotificationHandler<>.Handle`
  and `IPublisher.Publish` return `Task`. `IActionHandler<T>` declares `new ValueTask Handle` and
  `ActionHandler<T>` implements the inherited `Task` member explicitly with `.AsTask()`
  (`i-action-handler.cs`). The generated `Dispatch_*` methods are `async ValueTask<T>` that
  `await` a `Task<T>` from the handler, so the `ValueTask` is a wrapper around an allocation, not
  an allocation-free path. Nuru's changelog records that Nuru had to move its handlers from
  `ValueTask<T>` to `Task<T>` to adopt Mediator 14, which is the wrong direction for a
  source-generated AOT CLI.
- **Cost.** One `Task<T>` allocation per handler call even when the handler completes
  synchronously (State actions mostly do), plus the two-signature wart on `IActionHandler`.
- **Recommendation.** 15.0 contracts are `ValueTask` throughout: handlers, behaviors, the pipeline
  delegate, notification handlers, `IPublisher.Publish`, and both `ISender.Send` overloads. Delete
  the explicit `Task` shim from `ActionHandler<T>`. Consumers that genuinely need a `Task` call
  `.AsTask()` at the edge.

### F4. The pipeline delegate forces a closure per behavior per send.

- **Evidence.** `RequestHandlerDelegate<TResponse>(CancellationToken ct = default)` carries no
  request, so the generator must close over `request`, `handler`, `b1..bn`, and `cancellationToken`
  (`EmitNextDelegate`, `mediator-emitter.cs:521-540`): one lambda allocation per behavior per send,
  plus the `t == default ? cancellationToken : t` branch that exists only because the delegate may
  be called with no token. Behaviors are also resolved with `GetRequiredService` one by one per
  send (lines 486-499).
- **Cost.** For a State action with four scoped behaviors: four delegate allocations, five service
  resolutions, and five `async` state machines per action.
- **Recommendation.** Change the delegate to carry the message, which lets the generator cache
  `static readonly` delegates and removes every closure:

  ```csharp
  public delegate ValueTask<TResponse> MessageHandlerDelegate<TRequest, TResponse>(TRequest request, CancellationToken cancellationToken);
  public interface IPipelineBehavior<TRequest, TResponse> where TRequest : notnull
  {
    ValueTask<TResponse> Handle(TRequest request, MessageHandlerDelegate<TRequest, TResponse> next, CancellationToken cancellationToken);
  }
  ```

  Every State and Architecture behavior changes `next()` to `next(request, cancellationToken)`.
  That is a mechanical edit. Add an optional `Lifetime` to `[MediatorBehavior]` so singleton
  behaviors are resolved once into a static field; scoped behaviors (all of State's) are still
  resolved from the ambient scope in fixed order.

### F5. Fifteen interfaces for one dispatch shape.

- **Evidence.** Contracts define `IBaseRequest`, `IRequest`, `IRequest<T>`, `ICommand`,
  `ICommand<T>`, `IQuery<T>`, `IAction`, `IIdempotent`, `IIdempotentCommand`,
  `IIdempotentCommand<T>`, and handler interfaces `IRequestHandler<,>`, `IRequestHandler<>`,
  `ICommandHandler<>`, `ICommandHandler<,>`, `IQueryHandler<,>`, `IActionHandler<>`,
  `IIdempotentCommandHandler<>`, `IIdempotentCommandHandler<,>`. The graph builder
  (`message-graph-builder.cs`, 967 lines) must bind every handler interface per class and order
  them deterministically (task 013-007 exists because of this). Nuru re-derives "message kind" by
  string-matching interface names in the `TimeWarp.Mediator` namespace with a precedence trap that
  already caused a bug (`endpoint-extractor.cs:690-746`). `IBaseRequest` exists for MediatR's
  reflection scan; the generator does not need it.
- **Recommendation.** Keep the *message* kinds, because they carry meaning to each consumer
  (`IAction` for State, `ICommand` / `IQuery` / `IIdempotentCommand` for Nuru, plain `IRequest<T>`
  for Architecture). Delete `IBaseRequest`. Collapse the *handler* kinds to two:
  `IRequestHandler<TRequest, TResponse>` and `IRequestHandler<TRequest>`, and keep one abstract
  base per consumer convention that needs it (`ActionHandler<T>` for State). The kind is a
  property of the message, not of the handler. Expose the kind as data: a `MessageKind` field in
  the manifest and a small public `MessageKinds` helper in the Analyzers assembly that Nuru can
  call instead of string-matching. If the maintainer prefers to keep `ICommandHandler` /
  `IQueryHandler` for readability, they must become pure aliases with no generator binding logic
  of their own (section 7, decision D3).

### F6. Streams are dead weight on `ISender`.

- **Evidence.** `ISender` has five methods; two of them (`CreateStream`) throw
  `NotSupportedException` in the only dispatcher consumers use, and member-assembly stream handlers
  are TWM009. No consumer streams in production. Architecture's `ScopedSender` and State's test
  fakes must stub them to implement the interface.
- **Recommendation.** Remove `CreateStream`, `IStreamRequest<>`, `IStreamRequestHandler<,>`,
  `IStreamPipelineBehavior<,>`, and `StreamHandlerDelegate<>`. If streaming returns, it is a
  separate `IStreamSender` emitted only when a stream handler exists.

### F7. `ISender` / `IPublisher` / `IMediator` shape for 15.0.

- **Recommendation.** After F2, F3, F6:

  ```csharp
  public interface ISender
  {
    ValueTask<TResponse> Send<TResponse>(IRequest<TResponse> request, CancellationToken cancellationToken = default);
    ValueTask Send(IRequest request, CancellationToken cancellationToken = default);
    ValueTask<object?> Send(object request, CancellationToken cancellationToken = default); // late-bound; State JSON interop
  }
  public interface IPublisher
  {
    ValueTask Publish<TNotification>(TNotification notification, CancellationToken cancellationToken = default) where TNotification : INotification;
    ValueTask Publish(object notification, CancellationToken cancellationToken = default);
  }
  public interface ISender<TScope> : ISender { }
  public interface IPublisher<TScope> : IPublisher { }
  public interface IMediator : ISender, IPublisher { }
  ```

  `IMediator` stays because Nuru injects it and it costs one line. Hand-written test doubles
  (Architecture's `ScopedSender`, State's fakes) shrink from five methods to three.

### F8. `Unit` is a compatibility device; keep the type, fix the ergonomics.

- **Evidence.** `Unit` exists so that void requests can close `IPipelineBehavior<TRequest, Unit>`.
  State never names it. Nuru names it ~646 times because Nuru's generator reads the return type
  from `ICommand<T>`'s type argument, so "no output" is spelled `ICommand<Unit>`. Nuru's changelog
  records that `using static TimeWarp.Mediator.Unit` hides `System.Threading.Tasks.Task` because
  of the `Unit.Task` property.
- **Recommendation.** Keep `Unit` as the behavior-closure response type for void requests (the
  generator still emits `Dispatch_*` returning `ValueTask` for them). Rename `Unit.Task` to
  `Unit.ValueTask` (a cached `ValueTask<Unit>`), drop `IComparable` (it has no ordering). Nuru can
  then prefer the non-generic `ICommand` for no-output endpoints once F5 gives it the kind as data.

### F9. The generator re-walks the whole graph on every keystroke.

- **Evidence.** `mediator-generator.cs:45-48` builds the model from
  `context.CompilationProvider.Combine(options).Select(CreateModel)`. `CreateModel` walks
  `GlobalNamespace` of every member assembly (`membership.cs:145`, `message-graph-builder.cs:86`).
  The incrementality test (`incremental-generator-tests.cs:21-23`) asserts the Model step is
  `Unchanged` on an unrelated edit. `Unchanged` means the step *ran* and produced an equal value;
  `Cached` would mean it was skipped. So emission is deduplicated, but the 967-line graph build
  executes on every edit in the IDE. The spec (section 9) called for `ForAttributeWithMetadataName`
  plus symbol walking.
- **Recommendation.** Split the pipeline: handler and request candidates from the *host* via
  `ForAttributeWithMetadataName` / syntax providers keyed on the handler interfaces; referenced
  member assemblies from `MetadataReferencesProvider` keyed on reference identity, so they are
  rebuilt only when a reference changes. The test must assert `Cached`, not `Unchanged`, for the
  model step on an unrelated edit.

### F10. Four ways to join the graph.

- **Evidence.** Membership comes from the MSBuild property `TimeWarpMediatorAssembly`,
  `[assembly: MediatorAssembly]`, `[assembly: MediatorAssemblies(params Type[])]`, and
  `[MediatorModule("name")]` (string, graph membership only, not a pipeline). Consumers use the
  property (hosts) and `MediatorAssembly` (libraries). `MediatorAssemblies` and `MediatorModule`
  have zero consumers.
- **Recommendation.** Keep the property as the host default and `[assembly: MediatorAssembly]` as
  the library opt-in. Delete `MediatorAssemblies` and `MediatorModule`. Nuru currently reads
  `build_property.TimeWarpMediatorAssembly` and `build_property.TimeWarpMediatorProfile` to decide
  whether `AddGeneratedMediator` exists; after F11 the profile property disappears, and the
  generator should emit an assembly-level `[GeneratedMediator(typeof(Mediator))]` marker so Nuru
  can detect the generated dispatcher by metadata instead of by build property.

### F11. Three profiles, one of which is a name without a feature.

- **Evidence.** `TimeWarpMediatorProfile` is `Host`, `Aot`, or `Link`. `Aot` and `Link` are the
  same branch everywhere (`mediator-generator.cs:106-107`); the spec's Link profile (interceptors)
  was never built. The Aot profile changes semantics, not just emission: handlers become
  process-wide singletons in static fields, behaviors are silently dropped (TWM005), and there is
  no `IServiceProvider`. Only the AOT sample uses it. Nuru, the one consumer that ships
  container-free AOT CLIs, does not use it; instead Nuru builds a hidden
  `ServiceCollection` just to satisfy the Host profile's `IServiceProvider`
  (`interceptor-emitter.cs:431-486` in Nuru).
- **Cost.** A profile matrix in the generator, the manifest, the diagnostics (TWM005, TWM006), the
  tests, and the docs, for a profile no consumer runs.
- **Recommendation.** One emission. The generated `Mediator` takes an `IServiceProvider` and
  resolves *concrete* types with `GetRequiredService<T>`, which is already trim- and AOT-safe
  (the AOT-hostile part was open-generic resolution, and that is gone). Delete the Aot and Link
  profiles, `ServiceGen`, TWM005, and TWM006. A container-free host (Nuru) implements
  `IServiceProvider` over its own static graph; that is a one-method interface and Nuru's generator
  already knows every service. Behaviors then work in AOT hosts too.

### F12. Registration emits two descriptors per handler and two per closed behavior.

- **Evidence.** `EmitHandlerRegistrations` registers `AddScoped<Handler>()` and then
  `AddScoped<IRequestHandler<Req,Res>>(sp => sp.GetRequiredService<Handler>())`; for each request
  it registers `AddScoped<Behavior<Req,Res>>()` and `AddScoped<IPipelineBehavior<Req,Res>>(...)`
  (`mediator-emitter.cs:630-670`). The generated dispatch never resolves the interface mappings;
  they exist so DI-inspecting code (State's `LogTimeWarpStateMiddleware`, which reads
  `IServiceCollection` for `IPipelineBehavior<,>` descriptors) can see the pipeline.
- **Cost.** For a State host with N actions and M scoped behaviors: N + N·M interface descriptors
  on top of the N + M concrete ones, built at startup in Blazor WASM.
- **Recommendation.** Register concrete types only. Emit a static, generated
  `MediatorManifest` type (it already exists as JSON) with the ordered pipeline per request, and
  have State's middleware read that instead of inspecting `IServiceCollection`.

### F13. The DI extension class name is fixed and global.

- **Evidence.** The generator always emits
  `Microsoft.Extensions.DependencyInjection.GeneratedMediatorServiceCollectionExtensions`. It was
  made internal (task 010) to fix CS0121 across referenced hosts (issue #63), which in turn forces
  Nuru's tests to suppress CS0436 because `InternalsVisibleTo` re-exposes the duplicate, and
  Architecture still hand-writes uniquely named wrappers in two hosts.
- **Recommendation.** Emit the extension class into the host's generated namespace
  (`TimeWarpMediatorNamespace`, default `TimeWarp.Mediator.Generated`) with a name derived from
  it, keep it internal, and keep the method name `AddGeneratedMediator`. Two hosts in one
  solution then never collide, with or without `InternalsVisibleTo`.

### F14. Roslyn 4.8 floor is compatibility for hosts that cannot build net10.

- **Evidence.** `timewarp-mediator-generators.csproj:26-27` pins `Microsoft.CodeAnalysis.CSharp`
  to 4.8.0 "so older SDK/VS hosts load it". Consumers must target `net10.0`, which requires SDK 10
  and therefore a Roslyn far newer than 4.8. The floor keeps a dedicated test project
  (`timewarp-mediator-generators-roslyn-floor-tests`) alive and blocks newer incremental-generator
  and interceptor APIs.
- **Recommendation.** Raise the floor to the Roslyn that ships with the oldest SDK able to build
  `net10.0`, delete the floor test project, and keep `netstandard2.0` as the target (that part is a
  Roslyn requirement, not compatibility).

### F15. Four packages where two will do.

- **Evidence.** Contracts (runtime), Generators (generator + bundled Analyzers DLL, development
  dependency with suppressed dependencies so Contracts is not transitive), Analyzers (TWM001-004
  for libraries that do not run the generator), and the runtime. State libraries must reference
  Contracts + Analyzers and must *not* reference Generators (the csproj comment explains why).
- **Recommendation.** After F1: `TimeWarp.Mediator` is the contracts package (the name returns to
  its natural meaning once the reflection runtime is gone) and ships the TWM001-004 analyzer DLL
  as an analyzer asset, so every consumer gets missing-handler diagnostics without a second
  reference. `TimeWarp.Mediator.Generators` depends on it and stops bundling the analyzer. Two
  packages, no "which one do I add" table.

### F16. Strong naming and `InternalsVisibleTo` are MediatR conventions.

- **Evidence.** `timewarp-mediator.snk` signs the runtime and Contracts; the runtime tests must be
  signed so `InternalsVisibleTo` works. On `net10.0` strong names affect nothing except that
  pairing.
- **Recommendation.** With the runtime gone, nothing needs `InternalsVisibleTo`. Drop signing. Low
  priority; do it in the same task as F1 so the key leaves with the code that needed it.

### F17. The benchmark baseline is not a gate and measures the wrong path.

- **Evidence.** F2. Also, the comparison benchmark is Ping/Pong with no behaviors; the shape every
  State action runs is a void request behind four scoped behaviors, and nothing measures it.
- **Recommendation.** Record three benchmarks as the 15.0 baseline and the merge gate for the
  dispatcher tasks: `ISender.Send<TResponse>` Ping/Pong, `ISender<ClientPipeline>.Send` of a void
  action behind State's four behaviors (the `state/` test shapes already exist in
  `timewarp-mediator-generators-tests`), and `Send(object)`. Keep martinothamar as the external
  reference. Target: interface Ping/Pong within 1.5× of martinothamar and ≤ 24 B allocated.

### F18. Smaller debts to clear in passing

- `NotificationHandler<T>` (sync base class with explicit async implementation) has no consumer;
  delete.
- `Publish` is emitted as `async Task PublishCore(object)` with a most-derived-first switch, which
  boxes typed publishes through `object`; emit typed `Publish_X` arms inside `Publish<T>` like F2.
- `MediatorManifest.Json` is a string constant in the assembly; keep it as the single manifest but
  also emit it as the typed `MediatorManifest` from F12 so State and Nuru stop parsing JSON.
- `IIdempotent` is a marker with no enforcement, used by Nuru only as data. Keep it; it is one
  interface. Document that it is data for tooling, not a dispatch rule.
- The analyzers package and the generator share one graph builder but ship two copies of the DLL
  (Generators bundles Analyzers). F15 removes the duplication.

## 4. Target architecture for 15.0

**Packages.** `TimeWarp.Mediator` (contracts + TWM analyzer) and `TimeWarp.Mediator.Generators`.
Both `net10.0`-era; the generator stays `netstandard2.0` because Roslyn loads it in-process.

**Contracts** (everything `ValueTask`):

| Kind | Types |
|---|---|
| Messages | `IRequest`, `IRequest<TResponse>`; semantic markers `IAction : IRequest`, `ICommand : IRequest`, `ICommand<T> : IRequest<T>`, `IQuery<T> : IRequest<T>, IIdempotent`, `IIdempotentCommand(<T>) : ICommand(<T>), IIdempotent`; `INotification` |
| Handlers | `IRequestHandler<TRequest, TResponse>`, `IRequestHandler<TRequest>`, `INotificationHandler<TNotification>`; base `ActionHandler<TAction>` |
| Pipeline | `MessageHandlerDelegate<TRequest, TResponse>`, `IPipelineBehavior<TRequest, TResponse>` |
| Dispatch | `ISender`, `IPublisher`, `IMediator`, `ISender<TScope>`, `IPublisher<TScope>` |
| Membership | `[assembly: MediatorAssembly]`, `[MediatorScope(typeof(T))]`, `[assembly: MediatorBehavior(typeof(B<,>), order, Scope, Lifetime)]`, generated `[assembly: GeneratedMediator(typeof(Mediator))]` |
| Misc | `Unit` (with `Unit.Value`, `Unit.ValueTask`), `NoHandlerException` |

**Generated dispatcher.** One `internal sealed Mediator(IServiceProvider) : IMediator` per host
(plus `Sender_{Scope}` / `Publisher_{Scope}` per scope, as today). `Send<TResponse>` and
`Send(IRequest)` are type switches whose arms return the typed `ValueTask` from `Dispatch_*`
without boxing (F2). `Dispatch_*` resolves the handler and the scoped behaviors in compile-time
order and runs a chain of cached static delegates (F4). `Send(object)` and `Publish(object)` are
the only boxing paths. No profiles (F11).

**Registration.** `AddGeneratedMediator()` / `AddGeneratedMediator<TScope>()` register the
dispatcher and the concrete handler and behavior types only (F12), from an extension class in the
host's generated namespace (F13). The generated `MediatorManifest` type exposes the pipeline per
request and the message kind per request for tooling (F5, F12).

**Diagnostics.** TWM001-004 ship with the contracts package. TWM007-011 stay in the generator.
TWM005, TWM006 (Aot profile) and TWM009 (unsupported MediatR features) are deleted with the
features they describe.

**Generator pipeline.** Incremental by construction: host candidates via syntax providers,
referenced assemblies via `MetadataReferencesProvider`, model step `Cached` on unrelated edits (F9).

## 6. Consumer impact and migration

All three consumers are already generator-first, so the break is mechanical, not architectural.

**TimeWarp.State.**
- `StateActionHandler<T>` keeps deriving from `ActionHandler<T>`; the `Task` shim disappears.
- Seven behaviors change `Task<TResponse> Handle(req, RequestHandlerDelegate<TResponse> next, ct)` to
  `ValueTask<TResponse> Handle(req, MessageHandlerDelegate<TRequest,TResponse> next, ct)` and
  `next()` to `next(request, ct)`.
- `LogTimeWarpStateMiddleware` and `PipelineBehaviorRegistry` read the generated `MediatorManifest`
  instead of `IServiceCollection`.
- The action-set generator's emitted `await Sender.Send(new X.Action(...))` is unchanged
  (`ValueTask` awaits the same way).
- Test fakes drop the two `CreateStream` stubs.
- Packages: Contracts + Analyzers become one reference.

**TimeWarp.Architecture.**
- 62 handlers: `Task<OneOf<...>>` becomes `ValueTask<OneOf<...>>` (or keep `async` bodies; only the
  signature changes).
- `FluentValidationBehavior` and `GenericPipelineBehavior` take the F4 signature. This is the
  moment to replace the reflective `FromT1` construction with a generated or constrained
  failure-arm helper.
- `BaseFastEndpoint` awaits a `ValueTask`. `ScopedSender` shrinks to three methods.
- No contract renames: Architecture uses plain `IRequest<T>`, which stays.

**TimeWarp.Nuru.**
- Endpoint `Handler` classes: `ICommandHandler<X, Unit>` becomes `IRequestHandler<X, Unit>` (or
  stays, under decision D3) and returns `ValueTask<T>`, which is the shape Nuru wanted originally.
- Message-kind detection reads the generated manifest / `MessageKinds` helper instead of
  string-matching interface names.
- `__GetMediator()` stops building a hidden `ServiceCollection`; Nuru's generator emits a tiny
  `IServiceProvider` over its static graph and passes it to the generated `Mediator`.
- Detection of the generated mediator uses the `[GeneratedMediator]` assembly attribute instead
  of `build_property.TimeWarpMediatorProfile`.

## 7. Decisions needed from the maintainer

- **D1. Delete the reflection runtime in 15.0** (F1). Recommendation: yes, with no shim.
- **D2. `ValueTask` everywhere, including `ISender` and `IPublisher`** (F3, F7). Recommendation:
  yes. The alternative (ValueTask on handlers only) keeps a boxing hop at the interface.
- **D3. Collapse handler interfaces to `IRequestHandler` only** (F5). Recommendation: yes. If no,
  keep `ICommandHandler` / `IQueryHandler` as empty aliases with zero generator logic.
- **D4. Package names**: `TimeWarp.Mediator` becomes the contracts package (F15). Recommendation:
  yes; the major version signals the break, and it removes "Contracts" from every consumer csproj.
- **D5. Drop the Aot/Link profiles and require an `IServiceProvider`** (F11). Recommendation: yes,
  paired with a Nuru task to emit its own provider.
- **D6. Keep `Send(object)` on `ISender`** or move it to a separate `IUntypedSender`.
  Recommendation: keep on `ISender`; State needs it in the same `ClientPipeline` instance.
