# TimeWarp.Mediator 15.0.0-beta.5

A request in source can name a handler that another generator emits. Roslyn generators cannot see each other's output, so a handler TimeWarp.State generates was never dispatched. `GeneratedHandlerAttribute` is the declared fact. It is public and abstract. A derived attribute supplies `HandlerTypeName`, a constant type name relative to the request's containing type (or the request's namespace when the request is top-level). An attribute declared in another assembly passes that name as a constructor parameter named `handlerTypeName`. A default value is enough. A reference assembly does not keep the getter body, so a getter-only attribute on a ProjectReference is not the contract. The host candidate extractor accepts that attribute, including attributes found by walking base types, and the dispatcher emits a call to that name. Generated code may reference generated code, because every generator's output compiles together.

When the name is not a constant, the generator reports TWM012 on the attribute and tells the caller to add `handlerTypeName`. A name that is not a type name, and a type that exists but is not the request's `IRequestHandler`, use the same id with their own message. When the named handler still does not exist after every generator has run, the analyzer reports TWM012 on the attribute, including in a generator host. A library does not report that missing type: the host is where the other generator emits it. A generator host builds that check only when some type carries a `GeneratedHandlerAttribute`-derived attribute. Requests without the attribute are unchanged, including the unrelated-edit incrementality cache.

TimeWarp.State pins this version for its half of the same change.
