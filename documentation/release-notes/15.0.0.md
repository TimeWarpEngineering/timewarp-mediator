# TimeWarp.Mediator 15.0.0 release notes

15.0.0 is a breaking redesign of the 14.0.0 generated mediator. One dispatcher, two packages.
The parent review is task 021
(`documentation/design/2026-10-13-15.0-breaking-redesign-review.md`). Finding numbers below
are that review's section 3 and section 5.

Migration steps for TimeWarp.State, TimeWarp.Architecture, and TimeWarp.Nuru are in
[migration.md](../migration.md). The contract page is [architecture.md](../architecture.md).

The first prerelease of this surface is `15.0.0-beta.1`. Consumer dogfoods in those three
repos gate the push. `<Version>` in `source/Directory.Build.props` is the package version
that `dev pack` stamps.

## Breaking changes

| Change | Finding | Replacement |
|---|---|---|
| Reflection runtime package `TimeWarp.Mediator` (the 13.x/14.x reflection dispatcher), its tests, the container samples, the legacy benchmark, type forwards, and `.snk` signing | F1, F16 | The generated dispatcher. Product assemblies are unsigned. `Publish` awaits notification handlers sequentially |
| `TimeWarp.Mediator.Analyzers` as its own package | F15 | Analyzer asset `analyzers/dotnet/cs/TimeWarp.Mediator.Analyzers.dll` inside `TimeWarp.Mediator` (TWM001–TWM004). The analyzer project stays in the repo and is not packed |
| Package id `TimeWarp.Mediator.Contracts` | F15 | Package id `TimeWarp.Mediator` (contracts and the analyzer). Assembly name `TimeWarp.Mediator` |
| `IBaseRequest`, `ICommandHandler<>`, `ICommandHandler<,>`, `IQueryHandler<,>`, `IActionHandler<>`, `IIdempotentCommandHandler<>`, `IIdempotentCommandHandler<,>`, `NotificationHandler<T>` | F5, F18 | `IRequestHandler<TRequest, TResponse>`, `IRequestHandler<TRequest>`, `ActionHandler<TAction>`. Message kind is `MediatorManifest` data. Markers `ICommand`, `IQuery<T>`, `IAction`, `IIdempotentCommand` stay |
| `IStreamRequest<>`, `IStreamRequestHandler<,>`, `IStreamPipelineBehavior<,>`, `StreamHandlerDelegate<>`, both `CreateStream` overloads | F6 | None. TWM009 is retired |
| `RequestHandlerDelegate<TResponse>` | F4 | `MessageHandlerDelegate<TRequest, TResponse>`. Behaviors call `next(request, cancellationToken)` |
| `Task` / `Task<T>` on handlers, notification handlers, behaviors, `ISender`, and `IPublisher` | F3 | `ValueTask` / `ValueTask<T>` |
| Typed `Send` and `Dispatch_*` return the handler `ValueTask` directly. A null argument, `NoHandlerException`, and a throw before the handler returns a `ValueTask` escape `Send` as a thrown exception. 14.x `async` `Send` captured that throw in the returned task. A faulted or canceled `ValueTask` stays faulted until the caller awaits it | F2, F3, F7 | Await `Send`, or catch around the call, when projecting into `Enumerable.Select` / `Task.WhenAll`. Do not assume a synchronous failure is stored in the task |
| `MediatorAssembliesAttribute`, `MediatorModuleAttribute` | F10 | `[assembly: MediatorAssembly]`. The analyzer also reads MSBuild `TimeWarpMediatorAssembly`. The generator does not, so that property does not stop emission |
| `TimeWarpMediatorProfile`, Aot and Link emission, `ServiceGen`, TWM005, TWM006 | F11 | One emission. The host supplies `IServiceProvider`. Registered behaviors are woven. The AOT sample publishes with a behavior on that path |
| Reading `build_property.TimeWarpMediatorProfile` to decide whether `AddGeneratedMediator` exists | F10, F11 | `[assembly: GeneratedMediator(typeof(Mediator))]` (`GeneratedMediatorAttribute`) on the host assembly |
| `MediatorManifest` version 1 and its profile field | F11 | `MediatorManifest.Version` is 2. The JSON document has no profile field. `Requests` exposes kind, response, scope, and the ordered behavior list |
| Interface-mapped DI descriptors (`IRequestHandler<>`, `IPipelineBehavior<,>`, `INotificationHandler<>`) | F12 | Scoped registrations of the concrete handler and closed behavior types, plus `MediatorManifest` |
| `AddGeneratedMediator` emitted into a fixed global extension class | F13 | `internal` extension class in the host generated namespace (`TimeWarpMediatorNamespace`, default `TimeWarp.Mediator.Generated`) |
| Roslyn 4.8 floor and `tests/timewarp-mediator-generators-roslyn-floor-tests` | F14 | `Microsoft.CodeAnalysis.CSharp` 5.0.0 (the .NET 10 SDK compiler) |
| `Unit.Task` and `Unit : IComparable` | F8 | `Unit.Value` and `Unit.ValueTask`. Under `using static TimeWarp.Mediator.Unit`, signatures still bind to `System.Threading.Tasks.ValueTask`. A bare `ValueTask` in an expression is ambiguous (CS0229). Write `Unit.ValueTask` for the value and `System.Threading.Tasks.ValueTask` for the type's statics |
| Two-stack docs (`generated-vs-legacy.md`, profile page `m1-generated-mediator.md`, 13.x migration sections, `m1-benchmark-gap.md`) | F1 | [architecture.md](../architecture.md) and [migration.md](../migration.md) |

## Unchanged for callers

- `AddGeneratedMediator()` and `AddGeneratedMediator<TScope>()` remain the registration methods.
- `[assembly: MediatorAssembly]`, `[MediatorScope(typeof(TScope))]`, and
  `[assembly: MediatorBehavior(typeof(B<,>), order)]` with `Scope` stay.
- `ISender.Send(object)` stays on `ISender` (F7's sibling decision D6). It is the boxing path.
- `TimeWarpMediatorNamespace`, `TimeWarpMediatorAssembly`, and `TimeWarpMediatorGenerator` stay.
  The generator reads the namespace. The analyzer reads the other two. `TimeWarpMediatorAssembly=false`
  does not stop emission. A library that must not emit does not reference Generators.
- Trim and NativeAOT: the generated mediator is the path. Behaviors run under the AOT sample
  with IL2026, IL3050, and the other trim warnings treated as errors.
