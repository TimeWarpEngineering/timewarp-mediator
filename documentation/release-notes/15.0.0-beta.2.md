# TimeWarp.Mediator 15.0.0-beta.2

`15.0.0-beta.1` throws `TypeLoadException` under Blazor WebAssembly the first time a
handler completes a `ValueTask<Unit>`. `Unit.ValueTask` was a static auto-property, so
the `Unit` struct held a field of type `ValueTask<Unit>`. `ValueTask<T>` stores a `T`.
CoreCLR loads that cycle. The Mono WebAssembly loader reports a recursive type
definition for `System.Threading.Tasks.ValueTask<Unit>`.

`Unit.ValueTask` is an expression-bodied getter with no backing field. It still returns
a completed `ValueTask<Unit>` of `Unit.Value`. A reflection test fails if `Unit` declares
a static field of that type.

[migration.md](../migration.md) records the gaps found while moving TimeWarp.State onto
beta.1:

- `AddGeneratedMediator()` needs `using TimeWarp.Mediator.Generated` (or the namespace
  set by `TimeWarpMediatorNamespace`). That using is not implicit.
- `MediatorManifest` stays `internal`. The host passes `MediatorManifest.Json` to a
  library. A public type would collide when a library references two hosts (CS0433).
  CS0436 applies when a source type conflicts with an imported type.
- The manifest JSON has no `profile` key. Callers that switched on Aot or Link read
  `[assembly: GeneratedMediator(typeof(Mediator))]` and stop branching.
- Analyzers do not flow transitively. `PrivateAssets="all"` belongs on
  `TimeWarp.Mediator.Generators`. On `TimeWarp.Mediator` it drops the runtime DLL from
  a packed nuspec and from `dotnet publish`.
- `IActionHandler<TAction>` is `ActionHandler<TAction>` with
  `ValueTask Handle(TAction request, CancellationToken cancellationToken)`.
- `ValueTask<T>` does not convert from `Task<T>`, has no `ContinueWith`, and needs
  `AsTask()` before `Task.WhenAll`.
- `TimeWarpMediatorAssembly=false` does not stop emission.
- Under `using static TimeWarp.Mediator.Unit`, an expression writes `Unit.ValueTask`.

This repository has no Blazor WebAssembly lane. The load check is timewarp-state task
128 after that task re-pins `15.0.0-beta.2`.
